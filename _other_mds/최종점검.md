# 최종점검

## 개요
- 범위: Source/MyRatchet/Private의 .cpp, Source/MyRatchet/Public의 .h 전체
- 기준: 싱글플레이 GAS 기반 TPS

## 프레임워크/게임 흐름
- RAC_GameModeBase: 기본 GameModeBase 파생, 현재 로직 없음
- RAC_Cpp_GameMode: 플레이어 폰 BP(/Game/_M_RAC/Character/RAC_PlayerCharacter) 지정
- RAC_GameInstance: 현재 로직 없음
- RAC_GameState: 현재 로직 없음
- RAC_PlayerState: ASC + AttributeSet 생성, IAbilitySystemInterface 제공
- RAC_PlayerController: EnhancedInput 바인딩, HUD 위젯 생성, 조준 레이/타겟 포인트 계산

## 플레이어 캐릭터/이동
- RAC_CPP_Character
  - 이동/회전/카메라(스프링암, FOV 보간, 에임 카메라 오프셋)
  - 점프/글라이드(홀드 판정, 중력 스케일 변경)
  - 대쉬(무적/쿨다운/무브먼트 모드 전환)
  - 사망 처리(ASC 취소, 이동/충돌 비활성, 몽타주 후 디스폰)
  - 입력 기반 전투(에임, 사격, 탭 무기 교체)

## GAS: 스탯/이펙트
- RAC_AttributeSet
  - Health/MaxHealth, Ammo/MaxAmmo, Bolts, Raritanium, 경험/레벨, DamageMultiplier, DashCooldown
  - PostGameplayEffectExecute에서 clamp 및 UI 이벤트 브로드캐스트
- GE_AmmoCost
  - Instant, Ammo -1 적용

## 무기/전투
- RAC_WeaponData (DataAsset)
  - 무기 태그, 부여할 GA 목록, 스탯 수정 GE, 탄약/데미지/발사 타입
- RAC_WeaponManager (ActorComponent)
  - 무기 교체 시: 탄약 캐시, 기존 GA/GE 제거, 새 GE 적용, 탄약 복구, GA 부여
- RAC_ProjectileBase
  - 충돌/오버랩 기반 히트 처리
  - 같은 진영(플레이어-플레이어, 적-적) 기본 무시
  - GAS 대상이면 Health 직접 감소, 아니면 ApplyDamage 사용

## 플레이어/적 능력(Abilities)
- GA_AutoFire
  - 자동 연사, 탄약 체크 및 GE 소모
  - 화면 중앙 조준 라인트레이스로 목표점 계산, 프로젝타일 스폰
- GA_EnemyRangedAttack
  - 블랙보드 타겟 기반 투사체 발사
  - 소켓 탐색(StaticMesh -> SkeletalMesh) 후 스폰

## UI
- RAC_HUD_Widget
  - PlayerState의 AttributeSet 이벤트 + ASC delegate로 HP/Bolts/Ammo UI 갱신

## 적 캐릭터/AI
- EnemyCharacterBase
  - ASC/AttributeSet 보유, 기본 능력 부여
  - 공격 사거리/원거리 사거리 보관
  - 데미지 처리 및 사망 처리(몽타주 후 디스폰)
- EnemyMeleeCharacter / EnemyRangedCharacter / EnemyBossCharacter
  - EnemyType 세팅
- EnemyAIController
  - Perception(Sight) + BB/BT 초기화
  - 블랙보드에 공격 사거리/홈 위치/타겟/시야 값 설정
- BTTask_ActiveAbility / BTTask_TryActivateAbility
  - 태그 기반 능력 발동 시도
- BTTask_StopMovement / BTTask_ClearFocus
  - 이동 중지, 포커스 해제
- BTS_UpdateCombatData
  - 거리/시야/범위/마지막 위치/경과시간을 주기적으로 갱신
- YourProjectTypes
  - EEnemyType, EAIActionState 정의

## 기타 액터
- JumPad: 기본 Actor, 현재 로직 없음

## 잠재 이슈/점검 포인트
- PlayerController의 GetCrosshairRay에서 Deproject 성공 시 false 반환 로직 가능성(조건 반전 의심)
- EnemyAIController.h에 선언된 HandleControlledPawnDeath 및 IsDeadKey/ActionStateKey의 .cpp 정의 없음
- GameModeBase/GameInstance/GameState/WeaponData/EnemyAbilitySystemComponentBase/JumPad는 뼈대만 존재
- 글라이드 로직에서 StartGlide 호출이 Tick 조건과 중복되므로, 홀드 타이밍/낙하 조건 재검증 필요
- 사망 처리 로직(Player/Enemy)은 SetLifeSpan 기반으로 디스폰되므로 연출/루팅/리트라이 플로우 점검 필요

## 기능별 파일 매핑(요약)
- Frameworks: RAC_GameModeBase, RAC_GameInstance, RAC_GameState, RAC_PlayerController, RAC_PlayerState
- Player: RAC_CPP_Character, RAC_AttributeSet
- Combat: RAC_ProjectileBase
- Weapons: RAC_WeaponManager, RAC_WeaponData
- Abilities: GA_AutoFire, GA_EnemyRangedAttack, GE_AmmoCost
- UI: RAC_HUD_Widget
- Enemy/AI: EnemyCharacterBase, EnemyMeleeCharacter, EnemyRangedCharacter, EnemyBossCharacter, EnemyAIController, EnemyAbilitySystemComponentBase, BTTask_*, BTS_UpdateCombatData, YourProjectTypes
- TechActor: JumPad
- GameMode: RAC_Cpp_GameMode
